# 通常のページ移動で記録を引き継ぐデモ

2026-09-26。Vanillaデモに `?storage=session` モードを追加した。SDKの既存のsession保存を使い、TOP → ガイド → TOPのような、文書全体を読み直す遷移で記録を引き継ぐ。SDKの既定値はmemoryのままで、同意の保存や自動開始は追加していない。

## 起動と確認

```sh
npm run dev
```

[ページ横断のデモ](http://127.0.0.1:5183/?storage=session)を開く。計測を許可・開始して検索例を操作し、機能ガイドへ移動する。移動先でも許可・開始すると記録を復元する。確認完了を記録してトップへ戻り、再び許可・開始すると、完了したガイドが候補から除外される。具体的な操作は [README](../README.md#ページ移動後の記録を試す) を参照する。

確認パネルの末尾には、保存モードを変えるリンクと、記録がある項目の表示を置いた。通常のリンクと推薦リンクは保存モードを引き継ぐ。判定サーバー接続と併用する場合は `?engine=remote&storage=session` を使い、別ターミナルで `npm run dev:server` を起動する。通常起動の判定サーバーはモックである。

## 保存と許可を分ける

同一Origin・同じタブの直近30分の記録が対象。新しいページでは、許可・開始前に保存済みの記録を読み込まない。同意撤回とリセットでは保存分も削除する。保存が利用できない場合は、そのページ内のメモリで動作し、制約を画面へ表示する。

モード変更だけでは保存済みの記録は削除しない。削除してから通常モードへ戻る場合は、先に同意を撤回する。

ブラウザの履歴移動では、フォームの値が復元される場合がある。復元されたチェック状態を計測許可とは扱わず、画面表示をデモの実際の許可状態に合わせる。ページ全体がキャッシュから復帰した場合、sessionモードでは再読み込みする。古いメモリ内の記録で別ページの新しい記録を上書きしないためであり、再読み込み後も許可・開始を待つ。

## 検証する操作

`tests/e2e/session-demo.spec.ts` は、生成済みの静的HTMLで次の操作を確認する。

- TOPからガイドを経てTOPへ戻り、許可後に操作と確認完了の記録が復元される。撤回後の再読み込みでは戻らない。
- ブラウザの「戻る」でも、新しい許可を受けてから最新の記録を使う。停止中のリセットで保存分を削除する。
- 通常のリンクと推薦リンクで、保存モード・モック接続・推薦由来の固定マーカーが維持される。
- sessionStorageが利用できなくてもメモリで操作を記録し、保存の制約を表示する。

このデモ追加時点では、Safari製品版・iPhone/iPad実機の検証と、Jev実API試験は未実施。後続の実API試験は[比較レポート](14-jev-evaluation.md)を参照する。今回の変更はローカルデモのみで、公開設定や個人の運用情報は含めない。

## 実行結果

型検査・lint・Vanilla静的ビルドは成功。既存の回帰試験を含む28ケースをChromium・Firefox・WebKitで実行し、計84件が成功した。追加した4ケースは各エンジンで通過した。Chromiumの1280px幅と390px幅で表示を確認し、実行時エラーとモバイルの横方向のはみ出しはなかった。
