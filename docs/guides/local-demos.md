# ローカルデモで動きを確かめる

Imicueを初めて試す人向けの操作手順です。[READMEの起動手順](../../README.md#ローカルデモを動かす)を済ませ、`npm run dev` を動かしたまま、確認したいデモを開いてください。標準設定はAPIキー不要のRulesです。

## 基本デモで計測と判定を見る

[基本デモ](http://127.0.0.1:5183/)は、架空製品DemoContractの機能・料金・事例を使います。

1. 計測を許可し、「計測を開始」を押します。
2. 「検索例を開く」を押します。
3. 確認パネルで、操作の集計、辞書の説明、候補のスコアを確認します。判定は15秒以上の間隔で行います。
4. 候補を表示し、案内先へのリンクが出ることを確認します。

未許可の間は計測しません。停止すると直近の記録を維持し、同意撤回とリセットは記録と抑制履歴を削除します。リセット後は、計測中なら新しい記録を始めます。デモの同意操作はSDKの動作確認用です。実際のサイトでは、そのサイトの同意管理と接続してください。

## 100件の案内先を閲覧だけで試す

[100件の閲覧デモ](http://127.0.0.1:5183/catalog/)は、クリックや入力を使わず、表示した説明から案内先を選びます。100件はそれぞれ別のIDとURLを持ちます。

1. 計測を許可して開始します。
2. 1つ目の説明を、半分以上が見える状態で2秒以上表示します。
3. 2つ目の説明へスクロールし、30秒ほど表示します。
4. 「有効な閲覧」が2回以上、「クリック」「操作」が0回となり、契約書の全文検索ガイドが候補に出ることを確認します。
5. 「事例を調べる」に切り替え、再び許可・開始して同じ操作を行います。今度は営業チームの契約更新事例が候補になります。

同じ100件に対して、閲覧した説明に応じて案内先が変われば成功です。画面を隠したり別タブへ移ったりすると、表示時間の計測は止まります。判定は15秒以上の間隔で行うため、表示条件を満たした直後に案内が出るとは限りません。

このデモはメモリ保存です。ページを移動すると記録が消えるので、保存を試す場合は次のページ横断デモを使ってください。Jevの全件評価や容量制限については [100候補の評価記録](../21-candidate-scale.md)にまとめています。

## ページ移動後の記録を試す

[ページ横断デモ](http://127.0.0.1:5183/?storage=session)は、同じサイト・同じタブの直近30分をsessionStorageに保持します。

1. 計測を許可して開始し、「検索例を開く」を押します。
2. 「機能ガイド」に移動します。移動直後は、まだ保存済みの記録を読み込みません。
3. 移動先でも許可・開始すると、前のページの操作を復元します。「このガイドの確認を完了」を押します。
4. トップへ戻り、再び許可・開始します。確認パネル末尾の「記録がある項目」に前の操作が残り、完了した機能ガイドが推薦候補から外れることを確認します。
5. 「同意を撤回」を押し、再読み込み後に許可・開始します。撤回前の記録が戻らなければ、保存分の削除も成功です。

同意は保存しません。ブラウザの「戻る」でページがキャッシュから復帰した場合も、最新の保存記録を扱うため再読み込みし、許可・開始を待ちます。sessionStorageを利用できない場合はページ内のメモリで動作し、画面に制約を表示します。

通常モードへ切り替えるだけでは保存分を削除しません。消す場合は、切り替え前に同意を撤回してください。モックサーバーと併用する場合は `?engine=remote&storage=session` を指定します。[サーバーの起動手順](server-and-jev.md#モックサーバーに接続する)も参照してください。

## 静的ビルドを確かめる

```sh
npm run build
npm run preview
```

[静的デモ](http://127.0.0.1:4173/)は `dist/demo` を配信します。通常のガイドへのリンクは、計測を許可しなくても使えます。

紹介サイトを編集する場合は `npm run dev:site` を実行し、[ローカルの紹介サイト](http://127.0.0.1:5187/)を開きます。このサイトでは合成の閲覧記録をRulesで判定し、閲覧履歴の計測や実API通信は行いません。ビルドや検証は [紹介サイトの開発](../19-public-site-and-operations.md)を参照してください。

## 思った案内が出ないとき

まず計測が「計測中」か、集計に有効な閲覧や操作が増えているかを確認します。判定の詳細に見送り理由があれば、記録不足、候補の拮抗、直近の案内による抑制などを確認できます。別の場面を最初から試すには、リセットまたは同意撤回を使ってください。

「表示」は画面上の条件を満たした記録であり、読了を示しません。候補に出ることと、実際の訪問者に役立つことも別です。解決しない場合は、再現手順とブラウザを添えて [Issue](https://github.com/blanket11/imicue/issues)で相談できます。
