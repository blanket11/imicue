# 計測開始のタイミングを選ぶ

計測の開始・停止は、利用サイトが制御します。Imicueは同意UIや同意の要否を判断する機能を持ちません。ページ表示時に始める場合、既存の同意管理へ接続する場合、計測を無効にする場合で、`collection.mode` を選んでください。

## 3つのモード

| 設定 | 初期化時 | `start()` | 保存済み記録の復元 |
| --- | --- | --- | --- |
| `auto` | 計測を開始 | 停止後に再開 | 初期化時の開始処理で復元 |
| `manual` | 停止したまま | 計測を開始 | 初回の開始時に復元 |
| `disabled` | 計測しない | 開始しない | 復元しない |
| `collection` 省略 | 従来の互換動作で待機 | `setConsent('granted')` の後だけ開始 | 許可後の初回開始時に復元 |

復元は `storage: 'session'` の場合だけです。標準の保存先はメモリです。`disabled` でも、明示した `reset()` はそのTrackerの保存キーを削除します。モードを変える場合は、既存Trackerを破棄して新しく作ります。

## ページ表示時に自動で始める

```js
const tracker = createTracker({
  definition,
  pageId: 'home',
  collection: { mode: 'auto' },
});
```

初期化から戻る時点で、計測の開始処理が済んでいます。`setConsent()` は不要です。現在の状態と記録は `getState()` と `getSnapshot()` で取得し、その後の変更を購読します。初期化中の診断は、最初に `onDiagnostic()` を登録したときに通知されます。

`auto` は開始タイミングの設定です。Rulesならブラウザ内で判定し、Remote engineを指定した場合は観測が判定条件を満たすとサーバーへ送信します。サーバーやJevの利用条件は、[サーバー接続のガイド](server-and-jev.md)を参照してください。

## 同意管理やサイトの操作から始める

```js
const tracker = createTracker({
  definition,
  pageId: 'home',
  collection: { mode: 'manual' },
});

// 利用サイト側で開始してよいと判断したとき
tracker.start();

// 停止して記録も削除するとき
tracker.stop();
tracker.reset();
// 表示済みの案内UIも、利用サイト側で取り除きます。
```

この2つの操作を既存の同意管理や設定画面へ接続します。未開始の間は観測・保存の読み書き・判定通信をしません。`start()` を重ねて呼んでも、同じインスタンスでは二重計測しません。

`stop()` は進行中の表示区間を確定し、監視・タイマー・判定通信を停止します。記録は保持するため、その後の `start()` で再開できます。`reset()` は記録と抑制履歴を削除しますが、開始状態は変えません。停止と削除の両方が必要なら `stop()` → `reset()` の順に呼びます。

`destroy()` は停止とメモリ・購読の解放を行い、再利用できなくします。sessionStorageは保持します。保存分も削除するときは、破棄前に `stop()` → `reset()` を呼んでください。停止・リセット・ページ変更・破棄は古い判定応答を失効させます。

## 既存の `setConsent()` を使うコード

`collection` を省略した場合は、旧版と同じ動作を保ちます。

```js
const tracker = createTracker({ definition, pageId: 'home' });
tracker.setConsent('granted');
tracker.start();
// 撤回時：停止し、記録と保存分を削除
tracker.setConsent('denied');
```

既定動作をすぐに自動開始へ変えると、既存サイトで意図せず記録や通信が始まるため、省略時は互換動作を維持しています。新しい組み込みでは `collection.mode` を明示してください。明示した `manual` と、省略時の互換動作は異なります。

`setConsent()` は非推奨の互換APIとして残します。明示モードでも `setConsent('denied')` は停止・削除し、後続の `start()` を抑止します。再開するには `setConsent('granted')` の後に `start()` を呼びます。`disabled` は許可しても開始しません。

`getState()` の `collectionMode` は設定モード、省略時は `manual` です。`consentRequired` が `true` なら、省略による互換の許可条件が適用されています。明示モードでは `consent` が `unknown` のまま計測できます。この値から同意の取得状況を推定しないでください。

## ページ移動と保存

通常のページ移動で記録を引き継ぐ場合、各ページで同じ辞書・開始モードと `storage: 'session'` を指定します。同じOrigin・同じタブの直近30分が復元対象です。保存データが開始モードや同意状態を変更することはありません。

`manual` の移動先では再び `start()` を待ちます。`auto` は各ページの初期化時に復元します。停止したこと自体も保存しないため、次のページや再読み込み後の開始を抑えたい場合は、サイト側で設定を引き継ぎます。SPAでは同じTrackerに `setPage()` を呼びます。

## ローカルで確かめる

`npm run dev` を実行し、[開始モードのデモ](http://127.0.0.1:5183/collection/)を開きます。

1. 「自動開始・計測中」と表示され、「読書メモの検索例を開く」を押すと集計と案内が更新されることを確認します。
2. 「手動開始」に切り替えます。「計測を開始」を押すまで操作を記録せず、開始後は記録します。
3. 「計測しない」に切り替えます。開始ボタンは無効になり、検索例を開いても集計は空のままです。
4. 自動開始へ戻り「ページ移動後も記録を使う」を選び、検索例を開きます。「検索ガイドへ」→「トップへ戻る」で、前の操作が残ることを確認します。
5. 「記録を削除して停止」を押し、再読み込みします。自動開始で再開しますが、削除した操作は復元されません。

接続を確認する場合は `npm run dev:server` を別ターミナルで起動し、`?mode=manual&engine=remote` を指定します。標準のサーバーはモックで、実APIを呼びません。
