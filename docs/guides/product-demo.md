# 製品サイトを閲覧して、自動の案内を試す

架空のチーム向け進行管理サービス「PACELET」のサイトで、Imicueを組み込んだときの動きを試せます。製品紹介をスクロールすると、登録したセクションの表示を計測します。記録が揃うと、機能・事例・資料請求・お問い合わせの中から候補を選び、右下に案内を表示します。

APIキーは不要です。初期設定はブラウザ内で動くRulesで、判定データを外部へ送信しません。PACELETはデモ専用の架空の製品で、機能説明・事例・プランは実在のサービスの情報ではありません。

## 起動する

[開発環境の準備](../../README.md#ローカルデモを動かす)を済ませてから、次を実行します。

```sh
npm run dev:next
```

[製品サイトデモ](http://127.0.0.1:5186/)を開きます。静的出力で試す場合は次のコマンドを使い、[静的デモ](http://127.0.0.1:5184/)を開いてください。

```sh
npm run build:packages
npm run build:next
npm run preview:next
```

紹介サイト内の操作例は、用意した記録を切り替える説明用モックです。この製品サイトデモでは、実際のブラウザの表示時間とページ移動を計測します。Vanillaの基本デモや100候補のデモとは別の辞書・保存領域を使います。

## 閲覧に応じた案内を確認する

計測は `collection: { mode: 'auto' }` で自動開始します。通常の閲覧では、計測開始・判定・候補表示のボタンを押す必要はありません。

1. トップの製品紹介を開き、ボード機能の説明が半分以上見える状態で5秒ほど表示します。
2. 予定表の説明までスクロールして、30秒ほど表示します。
3. 右下に「機能について詳しく見る」が出ることを確認します。
4. 案内のリンクから機能ページへ移動します。通常のナビゲーションも利用できます。

別の案内を試すときは、左下の「Imicue Debug」を開いて「記録をリセット」を押し、パネルを閉じてから次の組み合わせを閲覧します。各説明は画面の半分以上が見える状態にし、1つ目を5秒、2つ目を30秒ほど表示するのが目安です。

| 閲覧する内容 | 主な案内先 |
| --- | --- |
| ボード機能・予定表 | 機能ページ |
| 制作チーム・複数拠点の事例 | 事例ページ |
| 共有範囲の説明・料金表 | 製品資料の請求ページ |
| FAQのデータ移行・導入までの流れ | お問い合わせページ |

判定は最低15秒間隔です。表示時間、ほかに見た内容、直前の案内によって結果は変わります。記録が少ない場合、候補の点数が近い場合、直近に案内を出した場合などは表示を見送ります。「料金を見たらお問い合わせ」と固定しているわけではありません。

右下のカードは、表示時に `shown`、リンクを押すと `clicked`、閉じると `dismissed` を記録します。案内から移動したページの表示は `recommendation` として扱い、通常の `direct` 閲覧とは分けます。表示されたことを、読了・好意・購入意思とは判断しません。

## ページ移動と記録の保持を確認する

同じタブ内のページ移動では、ひとつのTrackerを使い続けます。記録は `sessionStorage` に30分間保持し、再読み込み後も自動開始時に復元します。保存できないブラウザ設定ではメモリで動作し、Debugの診断に `storage_unavailable` が出ます。

現在のページ、閲覧条件を満たした案内先、閉じた案内先、完了した案内先は候補から外します。閲覧済み・完了済みの除外は保持期間内で有効です。案内を一度表示すると、次の案内は最低60秒間抑制します。表示したカードは最大30秒で消え、ページ移動・計測停止・リセットでも消えます。

フォームを操作中、モーダルを表示中、ページが非表示のときには案内を出しません。フォーム、ページ末尾の主要ボタン、開いたDebugパネルがカードの領域に重なる場合も表示を見送ります。案内が出なくても、通常のページリンクとフォームは利用できます。

## 資料請求・問い合わせの完了を試す

資料請求・お問い合わせページには、デモ専用フォームがあります。実際の情報を入力する必要はありません。空欄のままでも完了表示を試せます。

「資料請求の完了表示を試す」または「送信完了の表示を試す」を押すと、ページ内に完了メッセージを表示します。資料請求では製品資料の短いサンプルも表示します。外部への送信、メール配信、入力内容の保存は行いません。計測中の場合のみ、その案内先に `completed` を記録します。

JavaScriptが無効でも通常のリンクで各ページを閲覧できます。フォームは無効になり、送信できません。

## Debugで内部状態を調べる

左下の「Imicue Debug」から、計測状態、pageId、revision、Snapshot、Decision、候補スコア、見送り理由、診断、判定方式を確認できます。Escapeキーで閉じると、トリガーにフォーカスが戻ります。

| 操作 | 結果 |
| --- | --- |
| 記録をリセット | 保存分を含む記録を削除。計測中なら新たに記録する |
| 計測を停止 | 記録を保持して計測と判定を止める。ページ移動後も停止を維持する |
| 計測を開始 | 停止中の計測を再開する |
| 停止して記録を削除 | 計測を止め、保存分も削除する |
| Engineの切り替え | 記録を削除して、新しい判定方式で自動開始する |

停止状態とEngineの選択自体は保存しません。再読み込みするとRulesで自動開始します。手動開始・無効化を含むSDKの開始方式全体は、[開始モードのデモ](collection.md)で確認できます。

Remoteを選ぶ場合だけ、別ターミナルで `npm run dev:server` を起動してください。登録済みIDと数値をローカルの `http://127.0.0.1:5193/v1/decide` に送り、通常はモックで判定します。APIキーをこのサイトに渡す必要はありません。Next.jsの静的出力にPOST APIはありません。

## 実装と検証の範囲

辞書は `examples/product/definition.ts`、ページと表示UIは `examples/next-static` にあります。React用の専用SDKや外部のDebug UIライブラリは追加していません。Coreの判定条件も変更していません。

PlaywrightのChromium・Firefox・WebKitで、4種類の案内、見送り、表示・クリック・閉じる記録、SPA遷移、再読み込み、フォームの完了、入力を送信しないこと、遅れた応答の破棄、モバイル幅、キーボード、reduced-motion、JavaScript無効時を検証します。

```sh
npm run build
npx playwright test tests/e2e/next-static.spec.ts
```

これはローカルで動かす製品サイトの例です。このデモの公開、実フォーム送信、CRM連携、実利用者に対する推薦品質やCV率の評価、Safari製品版・スマートフォン実機での追加検証は行っていません。
