# 古い観測による推薦を抑え、実ブラウザ接続を確認した

2026-09-26。Jevに渡す推薦根拠を直近5分に最終観測されたシグナルへ絞った。「機能から料金へ関心が移った場面」では料金ガイドを選び、古い観測だけならAPIを呼ばずに見送る。既存12件と追加7件を各2回実行し、各ケースの推薦先・見送り理由は2回とも同じだった。**人による推薦品質の評価はまだ完了していない。**

## 時間の比較をコード側へ移した

[前回の実測](14-jev-evaluation.md)では、Jevが古い機能閲覧にも高い関連性を付け、新しい料金閲覧との差が小さくなっていた。今回、Coreで `lastSeenAgoMs <= 300000` のdirect観測へ絞り、最低観測量を再計算する。recentの個別イベントも同じ時間条件で絞る。モデル、質問、採点基準、出力の閾値は変更していない。

判定ポリシーは `jev-rubric-v2`。ブラウザ側でも鮮度条件を検証し、v1の応答や新しい観測がない状態での推薦を拒否する。サーバーとブラウザの成果物は一緒に更新する。Rulesは従来の半減期を維持する。

記録は同じタブ・同じOriginで30分保持でき、5分経過だけでは消さない。既読・完了・閉じたガイドの除外にも30分の記録を使う。たとえば10分前に読んだガイドを、鮮度制限を理由に再び推薦候補へ戻すことはない。

5分の鮮度制限と30分の記録・除外保持は、オーナーが今回の暫定動作として確認済み。5分が最適と実証したわけではない。5分ちょうどを含み、5分を超えた観測は外すため、境界で判断が切り替わる。さらにSnapshotはシグナル単位の30分集計であり、同じシグナルの再観測で過去の合計値も残る。行動一件ごとの滑らかな減衰や、厳密な5分集計が必要ならデータ契約から見直す。

## 19シナリオを各2回実行した

| 対象 | 1回あたりのAPI呼び出し | 結果 |

既存の「すべて弱い入力」は、30分前の観測を採点して閾値と比較する方式から、鮮度条件で観測不足として見送る方式へ変わった。元の期待値を変更して一致件数を増やすことはしていない。既存12件は、推薦するか見送るかと推薦先の比較ではすべてRulesと一致した。

追加ケースは最初のv2実API試験前に作成した。ただし、今回の修正目的を知って作成した少数ケースであり、独立した品質ベンチマークではない。

| 追加ケース | Jevの結果 |
| --- | --- |
| 10分前の機能閲覧だけ | 観測不足で見送り、APIなし |
| 5分ちょうどの機能閲覧 | 機能ガイド |

| 古い明示操作と新しい単発閲覧 | 観測不足で見送り、APIなし |

2回一致したことから長期の安定性や推薦精度は主張しない。シナリオ試験のAPIを含む判定時間は153〜306msだった。

## 3ブラウザから実Jevへ接続できた

Chromium・Firefox・WebKitで、Vanillaデモを操作し、HTTPサーバー経由で実Jevの結果を受け取った。2種類の操作を各ブラウザで試し、計6回のAPI呼び出しが成功した。

許可・開始前は送信なし、開始後はSnapshotのみをローカルサーバーへ送信、ブラウザから外部APIへの直接通信とAuthorizationヘッダーなし、実行時エラーなしを確認した。同意撤回後は観測と案内表示を消せた。

検索例を開く単発操作では、3ブラウザとも `below_threshold` で見送った。機能紹介のクリックと検索例を開く操作を合わせたケースでは、3ブラウザとも機能ガイドを推薦した。カードの表示、登録済みガイドへのリンク、同意撤回による非表示まで確認した。スコアは0.970〜0.977、provider confidenceは0.91〜0.93だった。モデルや閾値を変更せず、異なる観測で見送りと推薦の両方を確認できた。

Safari製品版は未実施。WebDriver試験には端末側の事前設定が必要で、WebKitの成功とSafari製品版の成功は分けて扱う。

## 入力表現を変えても、この12件の判断は同じだった

既存12件を、短いラベルだけ、日本語の辞書説明、英語の辞書説明で比較した。観測値・候補集合・共通ポリシー・質問・採点基準は固定し、モデルへ渡す意味の表現だけを変えた。ラベル版はシグナルのlabelまたはID、候補のtitle、トピックIDを使う。英語版は合成辞書の説明を手動で訳したもので、自動翻訳や実データは使っていない。

| 入力表現 | 実API回数 | 入力トークン | 既存期待値との一致 |
| --- | ---: | ---: | ---: |
| 短いラベル | 8 | 9,966 | 11/12 |
| 日本語の辞書説明 | 8 | 10,850 | 11/12 |
| 英語の辞書説明 | 8 | 10,712 | 11/12 |

最終判断は3方式で同じ。唯一の期待値との差は、前述した古い観測の見送り理由だった。ただしラベル自体にfeatures・pricing・casesなどの意味があり、候補も3件の単純な構成である。辞書説明の必要性や言語による品質差を判断するには、材料が足りない。多義的なラベルや複雑な製品に広げる際の確認は残る。

## ローカルで再現する

`.env.local` に `TYPESAFE_API_KEY` を設定したうえで、次を実行する。各コマンドは有料APIを呼び得る。再試行は行わず、1回の比較で最大12リクエストに制限する。

```sh
# 既存12件（実APIは8回）
RUN_JEV_EVALUATION=1 node --env-file=.env.local --import tsx --conditions=imicue-source scripts/evaluate-jev.ts

# 鮮度の追加7件（実APIは4回）
RUN_JEV_EVALUATION=1 JEV_EVALUATION_SUITE=freshness node --env-file=.env.local --import tsx --conditions=imicue-source scripts/evaluate-jev.ts

# 短いラベルだけ（実APIは8回）。英語版は値をdictionary-enに変える
RUN_JEV_EVALUATION=1 JEV_EVALUATION_VARIANT=labels node --env-file=.env.local --import tsx --conditions=imicue-source scripts/evaluate-jev.ts
```

結果はGit管理外の `test-results/jev-regression-evaluation.json`、`test-results/jev-freshness-evaluation.json` と日時付きファイルに保存する。入力表現を変えた結果は、ファイル名にlabelsまたはdictionary-enが付く。

ブラウザ接続試験は別ターミナルで `npm run dev` を起動し、5193番ポートのモックサーバーを停止してから実行する。

```sh
RUN_JEV_BROWSER=1 node --env-file=.env.local --import tsx --conditions=imicue-source scripts/jev-browser.ts

# 機能紹介のクリックと検索例の操作を組み合わせる
RUN_JEV_BROWSER=1 JEV_BROWSER_SCENARIO=feature-and-action node --env-file=.env.local --import tsx --conditions=imicue-source scripts/jev-browser.ts
```

各コマンドは試験中だけ実Jevサーバーを起動し、全ブラウザ合計3回を上限に呼び出す。終了後にサーバーを閉じ、`test-results/jev-browser.json` または `test-results/jev-browser-feature-and-action.json` に測定値を残す。通常のモックデモへ戻すには `npm run dev:server` を実行する。
