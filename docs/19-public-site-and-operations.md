# 紹介サイトの開発と確認

[Imicueの紹介サイト](https://imicue.push.tokyo/)では、ライブラリの用途、閲覧例によるRulesの比較、導入方法、利用上の制約を説明する。この文書はサイトを変更する開発者向け。ライブラリを試す場合は[ローカルデモ](guides/local-demos.md)を参照する。

## ローカルで表示する

Node.js 24.14.0 / npm 11.9.0で、リポジトリ直下から実行する。

```sh
npm ci
npm run dev:site
```

[紹介サイトのローカル版](http://127.0.0.1:5187/)を開く。計測デモの `npm run dev` は5183を使うため、同時に起動できる。5187を別のプロセスが使用している場合、別ポートへ自動移動せず起動を中止する。

配布用のファイルを確認するときは、開発サーバーを止めて次を実行する。

```sh
npm run build:site
npm run check:site
npm run preview:site
```

生成先は `dist/site`。HTML・CSS・JavaScriptだけで動く。`build:site` はCoreのソースを直接参照するため、パッケージの事前ビルドは不要。Viteの環境ファイル読み込みは無効にしている。プレビューも5187を使う。

## 比較デモの役割

訪問者の閲覧例を選ぶと、用意した合成Snapshotを実際のCoreのRulesエンジンへ渡す。観測記録、辞書に登録した意味と対応、判定結果を同時に表示し、選択した例に合わせて更新する。手順番号の進行を表すUIではない。

| 閲覧例 | 合成記録 | 確認する結果 |
| --- | --- | --- |
| 本の検索方法を読む | 検索機能の概要と詳細を各1回・30秒表示 | 読書メモの検索ガイドを選ぶ |
| 読書記録の整理方法を読む | 読書記録の概要と詳細を各1回・30秒表示 | 読みかけの本を整理するガイドを選ぶ |
| 両方を同じくらい読む | 上の4件を同じ条件で表示 | 候補差がないため見送る |
| 閲覧記録がない | 記録なし | 根拠不足で見送る |

この表は合成データの条件であり、画面を実際に30秒眺める必要はない。比較用の候補は2件。Rulesは辞書の明示的な関連付けから採点し、説明文の意味をAIで解釈しない。比較値は関心や購入の確率として表示しない。

紹介サイトではTrackerを起動せず、訪問者自身の閲覧履歴、Web Storage、Cookieを使わない。Jevへの接続やAPIキーも不要。実際の計測、ページ移動後の保存、100候補の判定、Jev接続を確認する場合は[ローカルデモ](guides/local-demos.md)を使う。

外部フォントや解析タグは読み込まない。GitHubへのリンクを選ぶと遷移先への通信は発生する。配信サービスによるアクセスログの扱いは、そのサービスの設定と方針に従う。

## 表示と配布物を検証する

```sh
npm run build:site
npm run check:site
npm run test:site
```

`test:site` はビルド済みサイトを4187で配信し、Chromium・Firefox・WebKitで検査する。閲覧例と結果の対応、記録と辞書の更新、初期状態への復帰、キーボード操作、コピー成功・拒否、幅320/390/1280pxでのはみ出し、JavaScript無効時の案内を確認する。Storageと判定APIを使わないこと、CSPがインラインスクリプトやfetchを拒否すること、404から戻れることも対象にする。

`check:site` はファイルの種類、参照先、容量、ヘッダー、サーバー専用設定の混入を検査する。全体の `npm run check` にもサイトのビルド・検査・ブラウザ試験を含める。Safari製品版とモバイル実機の紹介サイト確認は、PlaywrightのWebKit試験とは別に扱う。

## 更新を公開する

紹介サイトはCloudflare Pagesで配信している。リポジトリの更新はPull requestでレビューし、mainへ取り込む。配信側の設定と確認事項は[Cloudflare Pagesでの配信](20-cloudflare-pages.md)を参照する。

公開対象は `dist/site` の静的ファイル。ローカルの計測デモ、判定サーバー、Jevのキー、評価の生ログは含めない。公開サイトの内容と、手元の作業ブランチの内容は、マージと配信が完了するまで異なる場合がある。

## Jevの本番利用は別に準備する

本番の判定サーバーには、Node.js互換の実行環境、複数プロセスで共有する利用制限、費用上限、同時実行制限、障害時の停止方法が必要。開発用のメモリ内カウンターを指定したままproductionモードは起動できない。

共有基盤を用意したうえで、競合・再起動・上限到達・基盤障害を試験する。APIキーはサーバーの秘密設定で渡し、許可Originと辞書を固定する。ログへキー、入力本文、個人を特定する情報を残さない。費用はその時点の料金と、利用見込み・実測トークン数から見積もる。

実APIのローカル結果は[100候補の評価記録](21-candidate-scale.md)を参照する。人による品質評価、実サイトの辞書での検証、モバイル実機、継続的な負荷確認は残る。紹介サイトの公開だけで、これらを完了したとは扱わない。
