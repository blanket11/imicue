# 公開用サイトのローカル版と運用案

2026-09-26。Imicueの仕組み、操作できるRulesデモ、ローカル導入手順、利用上の制約をまとめたサイトを追加した。公開用の候補であり、まだデプロイしていない。npmパッケージも未公開。

## ローカルで確認する

Node.js 24.14.0 / npm 11.9.0を使う。

```sh
npm ci
npm run dev:site
```

[公開用サイトのローカル版](http://127.0.0.1:5187/)を開く。従来の計測デモは `npm run dev` で5183を使うため、同時に起動できる。同じ5187で別のサーバーが動いていれば、別ポートへ自動移動せず起動を中止する。

配布するファイルと同じ状態で試す場合は、開発サーバーを止めて次を実行する。

```sh
npm run build:site
npm run preview:site
```

生成先は `dist/site`。HTML・CSS・JavaScriptだけで動く。`build:site` はCoreのソースを直接参照するため、パッケージの事前ビルドは不要。Viteの環境ファイル読み込みは無効にしている。

## デモで確かめられること

操作を選ぶと、固定の合成記録を実際のCoreのRulesエンジンへ渡す。結果の文章だけを切り替えるモックではない。

| 選ぶ操作 | 合成記録 | 結果 |
| --- | --- | --- |
| 機能を使う | 機能に関連する操作1回 | 機能ガイド |
| 料金を調べる | 料金に関連する操作1回 | 料金ガイド |
| どちらも同じくらい見る | 機能と料金をそれぞれ2回表示 | 候補差がないため見送り |
| まだ操作していない | 記録なし | 根拠不足で見送り |

「この判定の根拠を見る」で合成記録とRulesの比較値を確認できる。値は関心や購入の確率ではない。「最初の状態に戻す」は選択と結果を初期状態に戻す。

このサイトではTrackerを起動せず、実際の閲覧履歴、Web Storage、Cookieを使わない。Jevへの接続やAPIキーも不要。ページ横断の保存やJev判定を試す場合は、[従来の計測デモ](../README.md#ページ移動後の記録を試す)を使う。

外部フォントや解析タグは読み込まない。GitHubへのリンクを選ぶと、遷移先への通信は発生する。公開後の配信サービスによるアクセスログは別途、そのサービスの設定と方針を確認する。

## 最初の公開は静的サイト

まずは `dist/site` の配信を行う方針とした。この範囲なら公開用JevサーバーやAPI課金は不要で、仕組みと使い方を紹介できる。配信先はCloudflare Pagesに決定し、[設定と確認手順](20-cloudflare-pages.md)を追加した。サービスへの接続・デプロイはまだ行っていない。

2026-09-26に公式資料で確認した候補は次のとおり。無料枠の条件は公開時にも確認する。

| 候補 | このサイトとの関係 | 費用・制約 |
| --- | --- | --- |
| Cloudflare Pages | 静的ファイルを配信でき、既存DNSを維持したサブドメイン接続が可能 | Functionsを使わない静的リクエストは無料・回数制限なし。Freeでは月500ビルド、同時1ビルド、1回20分、最大2万ファイル、1ファイル25MiB |
| GitHub Pages | 公開リポジトリから静的ファイルを配信でき、独自ドメインも利用可能 | 公開リポジトリではGitHub Freeから利用可能。判定サーバーの実行先にはならない |

出典: [Cloudflareの静的配信料金](https://developers.cloudflare.com/pages/functions/pricing/)、[Pagesの制限](https://developers.cloudflare.com/pages/platform/limits/)、[カスタムドメイン](https://developers.cloudflare.com/pages/configuration/custom-domains/)、[GitHub Pagesの概要](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

比較の後、Cloudflare Pagesを採用する方針を確認した。サブドメインのためにネームサーバーを移す必要がない点を重視した。ドメインの維持費や将来の有料プランは、この静的配信の無料枠とは別に扱う。

## 公開を決めた後の作業順

1. 変更をPRでレビューし、必要なチェックと承認を経てmainへマージする。mainへの直接反映は行わない。サイト内の仕様書リンクとclone手順はmainを参照するため、マージ前のサイトを正式公開しない。
2. 配信サービスと公開範囲を確定する。管理アカウント、認証情報、DNS管理に関する個人情報はリポジトリに保存しない。
3. [Cloudflare Pagesの設定表](20-cloudflare-pages.md#pagesのgit連携に設定する値)に従い、依存関係のインストール、ビルド、出力検査を実行する。出力は `dist/site` とし、Node.js・npmのバージョンも配信サービス上で確認する。参照: [公式ビルド設定](https://developers.cloudflare.com/pages/configuration/build-configuration/)。
4. 仮の公開URLでHTTPS、表示、リンク、4つの判定、コピー、外部通信を確認する。CSPなどの配信ヘッダーとキャッシュ方針も、実際の配信環境で反映を確認する。
5. カスタムドメインを接続する。Cloudflare Pagesでは管理画面で先にドメインを追加し、その画面で示された接続先へCNAMEを設定する。接続先を推測しない。DNS設定後に証明書の発行とHTTPSを確認する。
6. 公開URLで再確認し、問題があれば直前のデプロイへ戻せることを確かめる。公開の事実と利用者向けURLは、公開範囲の承認に合わせて案内する。

DNSへのアクセスやサービスの連携が必要になるのは、この公開操作の段階。ローカル版の確認には不要。

## Jevを公開サイトで動かす前に残ること

静的サイトの公開と、Jevを使う判定サーバーの公開は別の作業単位とする。実APIのローカル確認結果は [採点基準と再検証](18-jev-relevance-rubric.md) を参照。

本番の実装には、Node.js互換の実行環境、複数プロセスで共有する原子的な利用枠カウンター、日次・月次の上限、同時実行制限、障害時の停止方法が必要。現在の開発用メモリカウンターでは、公開サーバーを起動しない安全条件を維持している。

配信先を選んでから共有基盤を実装し、競合・再起動・上限到達・基盤障害の試験を追加する。APIキーはサーバーの秘密設定で渡し、許可Originと辞書を固定する。ログにはキー、入力本文、個人を特定できる情報を残さない。利用見込みに基づくAPI費用の上限は、その時点の料金と実測トークン数で決める。未検証のEdge互換性や無料運用を前提にしない。

人による残りの推薦品質レビュー、iPhone/iPad実機確認、npm名・公開権限・バージョンの確認も残っている。サイトの公開だけでこれらを完了扱いにしない。

## ローカル検証

`npm run test:site` はビルド済みのサイトを4187で配信し、Chromium・Firefox・WebKitで9件を確認する。4つの判定、根拠の表示、リセット、Storageを利用しないこと、外部API通信がないこと、キーボード操作、コピー成功・拒否、幅320/390/1280pxでの横方向のはみ出し、JavaScript無効時の案内とリンクを対象とする。コピーは権限に依存しないようテスト内で成功・拒否を再現する。

Codex内ブラウザでもデスクトップと幅320/390pxの表示・操作を確認した。新しいサイトのSafari製品版とモバイル実機は未検証。VanillaデモのSafari試験とは区別する。

配布検査には `dist/site` を追加し、サーバー専用SDKやキー設定名の混入を検査する。`npm run check` にサイトのビルドと9件の試験を含めた。今回の作業では実APIを呼ばず、公開操作、DNS変更、npm公開、既存サイトへの導入、Issue・Project変更も行っていない。

全体の `npm run check` は成功した。型検査・lint、Vitest 233件、ビルド、配布・梱包検査、Rules評価12件、既存デモのE2E 84件、サイトのE2E 9件が通った。
