# 内容が一致する単発操作を案内につなげる

2026-09-26。「内容が明確に一致すれば、1回の操作でもガイドを案内する」方針を確認し、Jevの採点基準を更新した。[前回の確認表](17-recommendation-review.md)で見送られていたQ01・Q02・Q12は、変更後の2回とも期待するガイドを推薦した。関連候補がない場合や、候補差が小さい場合は引き続き見送った。

## 変更したもの

以前の段階2と3は、どちらも明示操作を根拠にできる説明になっていた。今回は、段階2を「同じ具体的なテーマの周辺情報」、段階3を「観測した機能・操作・内容そのものの説明」とした。段階3では言い換えを含む具体的な一致を評価し、明示操作は1回でもよいとした。[採点基準の全文と契約](04-decision-engines.md#5-jevengine)を参照する。

モデルはjev-1.13.0を維持し、スコア0.65、provider confidence 0.60、次点との差0.10の閾値も変更していない。直近5分の根拠、30分の記録・候補除外、最低観測量は従来どおりコードで検査する。

判定ポリシーは `jev-rubric-v3`。ブラウザ側はv1・v2の応答を拒否するため、サーバーとブラウザの成果物を一緒に更新する。型の構造や保存形式、Rulesの判定は変更していない。

## 説明を省いた入力では誤案内もあった

同じv3でラベル中心の入力も1回比較した。12件中1件を推薦、11件を見送り、許容案に入ったのは7件だった。Q11では「操作」というラベルだけではPDFの文字抽出だと分からず、唯一の候補である料金ガイドを推薦した。合成シナリオの本来の操作に対しては無関係な案内である。

辞書付きではQ11を2回とも見送った。実装ではサーバーが持つ具体的なdescriptionまたはmodelDescriptionを渡す。ラベルだけの比較は評価スクリプト内に限定する。説明が不足した入力でも適切に判断できるとは主張しない。

## ローカルで再確認する

通常の確認は `npm run check`。実APIは呼ばない。5184・5185・5193で手動プレビューを起動している場合は、E2E実行前に停止する。

実APIで複雑な辞書を再評価する場合は、Git管理外の `.env.local` にTYPESAFE_API_KEYを設定し、実API利用が許可された環境で次を実行する。最大12リクエストで再試行しない。

```sh
RUN_JEV_EVALUATION=1 JEV_EVALUATION_SUITE=semantic node --env-file=.env.local --import tsx --conditions=imicue-source scripts/evaluate-jev.ts
```

基本12件はJEV_EVALUATION_SUITEを省略し、鮮度7件は `JEV_EVALUATION_SUITE=freshness` を指定する。JSON結果はGit管理外のtest-resultsへ保存する。各結果のpolicyVersionで採点基準を区別できる。人による全件レビューは未完了として記録する。

公開用サイト、本番の共有利用制限、残りの意味評価、モバイル実機は後続作業。npm公開、デプロイ、DNS設定、実サイトへの導入、Issue・Project変更は行っていない。
