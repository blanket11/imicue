# セキュリティ・プライバシー・判定エンドポイント

本書はライブラリの技術要件であり、法令への適合や、実サイトでの利用承認を保証するものではない。実際の導入者が利用目的、同意・通知、外部送信、契約、組織の規程を確認する。

## 1. 信頼境界

| 領域 | 扱い |
| --- | --- |
| サーバー設定の辞書・候補・判定ポリシー | レビュー済みの設定。ただし入力形式・URLを検証する |
| ブラウザから届いたID・数値・outcome | 改変可能な未信頼データ |
| siteId / snapshotId / pageViewId | 公開または一時的な識別子。認証トークンではない |
| モデル応答 | 型・範囲・候補整合性を再検証する必要がある |
| 推薦先のHTML | ライブラリから生成・実行しない |

観測結果は個人の真実でも、課金・認可に使える検証済み事実でもない。IDを改ざんすれば別の許可済み候補が返り得ることは、推薦用途の残余リスクとして受け入れる。ただし任意APIを中継する踏み台にはしない。

## 2. 収集しないデータ

DOMのinnerText/innerHTML、input/textarea/contenteditableの内容、検索語、メールアドレス、会員ID、入力キーの値、座標、IPアドレスやUser-Agentのモデル送信、URLのquery/hash、referrer全文を自動収集しない。

pageIdは利用者が登録した固定値を渡す。履歴APIやfetch/XHRを横取りして全操作を収集しない。通信でIP等がインフラに見えることと、Imicueが人物情報を収集・保管しない設計であることは区別する。

個人名がないことをもって「完全匿名」「同意不要」と宣伝しない。データの扱いは利用目的や組み合わせでも変わるため、SDKが法的判定を行わない。

## 3. 同意と保存

初期状態は未許可。観測・保存データの読み込み・保存・判定通信は、利用サイトからの明示的な許可とstartがあるまで開始しない。静的なJS自体の取得がCDNのアクセスログを発生させる可能性は別問題なので、厳格なサイトではscriptの読み込み自体を同意後に行うか自己配信する。

同意撤回はobserver、イベント、timer、進行中通信を停止し、Imicue自身のメモリ・storageを削除する。失効generationを更新して、後から届いたレスポンスからデータやUIが復活しないようにする。

sessionStorageはopt-in。既定のmemoryを勝手に永続化しない。サーバーは観測payloadを永続保存しない。通常ログは状態コード、処理時間、容量、エンジン/定義/ポリシーのバージョンなど最小限に限定する。実データをIssue・コミット・エラーメッセージへ転載しない。

Jevの保存・学習・保持ポリシーは導入時に公式規約を確認する。サービスの保持条件を推測して「外部には保存されない」と記載しない。通常のテストとCIでは実ユーザーのデータも有料APIも使用しない。実APIの検証は合成データを使う別コマンドで実行する。

## 4. HTTP契約

v0.1の例は、利用者が管理する単一サイト用の `POST /v1/decide`。マルチテナントSaaSではない。

リクエストContent-Typeはapplication/json、bodyは [Snapshot](02-data-contracts.md#3-観測スナップショット)。プロンプト、criteria、APIキー、provider、baseURL、自由候補URL、自由なdictionaryを受け取らない。

| 状況 | 応答 |
| --- | --- |
| 正常な推薦または意味的な見送り | 200 + Decision |
| 型不正・未知ID・重複行・未知フィールド | 400 + 固定エラーコード |
| 許可していないOrigin | 403 |
| 定義バージョンが存在しない | 409 + definition_mismatch |
| 許容量超過 | 413 |
| サーバー利用制限に到達 | 429 + Retry-After |
| プロバイダー接続不可 | 503 + engine_unavailable |
| サーバーの全体タイムアウト | 504 + engine_unavailable |

エラーbodyは `{ "error": { "code": "..." } }` のような固定形式で、受信本文・スタック・外部APIの認証詳細を反射しない。HTTPエラーをBrowserが診断し、必要に応じてtechnical abstainへ変換する。400/409/413を修正せず自動再送しない。

レスポンスは `Cache-Control: no-store`。ブラウザはcredentials='omit'を初期値にする。同一originが標準、クロスoriginは許可リストを明示する。通信はlocalhost開発以外HTTPSを要求する。

## 5. 入力と呼び出し容量

初期の受信body上限は32KiB。Content-Lengthだけでなく実際に読んだbyte数を検査する。過大なJSONを無制限に読み終えてから判定しない。

数値は有限・非負・整数、windowMsは最大30分、各観測のvisibleMsはwindowMs以下、ageはwindow内、カウントは各1,000以下。定義内の全IDをown propertyで照合する。prototype pollution、異常な配列長、未知プロパティを拒否する。

定義JSON全体は2MiB、Jev向けにCoreで意味展開した入力全体は1MiB以下。Jevへ送るJSONは1要求64KiB、共通stateと候補1件の質問を含む要求は24KiB以下とする。全候補を最大8要求へ分割できない場合は、送信前にcapacity_limitとする。これらはbyte単位の資源保護であり、モデルのtoken上限を保証するものではない。説明を黙って切り詰めず、候補数だけでなく説明の長さと観測数も診断する。候補数等は [判定仕様](04-decision-engines.md) に従う。

## 6. APIキーと課金乱用対策

TYPESAFE_API_KEYはサーバー環境変数のみ。NEXT_PUBLIC等の公開変数、HTML属性、localStorage、CDN script、GitHub Projectの本文には置かない。Browser bundleはserverパッケージやJev SDKをimportしない。[SDKの制約 S5](08-references-and-decisions.md#s5)

CORSはブラウザのアクセス制御の一部であり、呼び出し元の身元を保証しない。OriginやsiteIdをチェックしただけでAPIが守られたと扱わない。[OWASP S9](08-references-and-decisions.md#s9)

サーバーには利用制限フックを設け、少なくとも同時プロバイダー呼び出し数、単位時間の全体呼び出し数、1日あたりの全体呼び出し上限をプロバイダー呼び出し前に確保する。応答失敗やtimeoutも消費に含め、無限再試行で上限を迂回させない。

判定受付と外部API試行を別々に制限する。外部APIは全分割の回数枠を先に原子的に予約し、1試行ごとに同時実行枠を確保する。送信しなかった枠だけを返却し、送信後の失敗・タイムアウトは消費に含める。Abort後もローカルの呼び出し処理が完了するまで同時実行枠を保持する。提供元内部の処理停止までは保証しない。

ローカルデモ用の初期例は同時2件、全体30回/分、全体100回/日。これは価格・利用量の見積もりではなく、誤実装時の被害を制限する仮の設定である。失敗時に残量を自動で戻さない。

単一Nodeプロセスのメモリ内limiterは開発用に限る。再起動・複数プロセス・serverlessでは上限が共有されないため、本番は原子的な共有カウンターまたは外部gatewayが必要。productionモードでは、判定受付の共有limiterに加え、Jev engineに共有ProviderUsageLimiterを指定する。どちらかが開発用の場合は起動を拒否する。共有基盤そのものの構築はv0.1のスコープ外。

clientのsession IDに依存する制限だけでは容易に回避できる。IP単位の制限を追加する場合も唯一の対策にせず、保存範囲・期間を別途検討する。

ProviderUsageLimiterは `reservePlan(attempts)` で全試行数を予約し、各 `acquireAttempt()` で1回を消費して並列枠を確保する。共有実装は、未実行の予約・実行中の枠・分/日の履歴を同じ原子的な境界で管理する。`release()` は二重実行しても二重返却しない。送信済み分の課金が中断で取り消される前提にはしない。

productionのhandlerは、共有provider limiterに結び付いた `createJevEngine` のengineを検証する。単に `name: 'jev'` とした独自engineは検証できないため拒否する。開発モックはdevelopmentモードで使う。独自Jev engineの本番対応は別途provider制限の契約を設計する必要がある。

この検証はfactoryが返したオブジェクトに結び付くため、engineはそのままhandlerへ渡す。スプレッド構文で複製したengineも本番では拒否する。使用量の計測には `onUsage` を使い、engineを複製してラップしない。

エンドポイントはブラウザからの指定を使って外部URLをfetchしない。辞書のhrefへサーバーからアクセスして本文を自動収集する機能も作らない。

## 7. Prompt injectionと表示内容

モデルへ渡す自然文はサーバーの管理者がレビューしたdescription/criteriaに限定する。訪問者が変更したdata属性はID検証を通るだけで、自由な指示文を増やせない。

それでもモデルの意味判断は絶対ではない。合成の敵対的説明を使ったテストを設け、辞書テキスト内の指示を運用ルールとして実行しない。モデルの応答からURL、コード、HTMLを生成して使用しない。

表示は登録済みcontentIdをローカル定義に解決する。Reactの通常の文字列描画やtextContentを使い、innerHTML/dangerouslySetInnerHTMLへ流さない。hrefも [定義検証](02-data-contracts.md#2-定義ファイル) の条件で再確認する。

## 8. 公開リポジトリと供給経路

`.gitignore` はnode_modules、ビルド成果物、テスト出力、`.env` / `.env.*`、ログを除外している。`.env.example` だけを例外とし、ダミー値のみを追跡する。すでに追跡されているファイルにはignoreが適用されないため、コミット前に差分も確認する。

勤務先由来のコード・内部資料・営業データ・ユーザーデータを再利用しない。テストデータは合成し、公開のプロジェクトページも秘密保管場所にしない。漏えい済みのキーはファイル削除だけで対処完了にせず、失効・再発行を行う。

workspacesは `private: true` で、npmには未公開。公開名、npmスコープ、CDN URLの利用可否はパッケージ公開時に確認する。script配布では固定バージョンの自己配信、SRI、CSPを組み合わせる。[配布ファイルの利用手順](guides/distribution.md)を参照する。

## 9. 本番導入前のゲート

実APIの動作確認、ルール/Jevの比較、キー隔離、入力検証、同意撤回、制限、予算、観測ログの保持、サイトのプライバシー説明、組織の承認を確認してから検討する。

このライブラリのデモが動いたことを理由に、勤務先サイトへタグを設置したり、既存ユーザーの行動を外部APIへ送ったりしない。
