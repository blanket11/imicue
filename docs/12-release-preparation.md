# M5の公開準備と評価

2026-09-26。M4のローカル成果物に、パッケージごとの説明、貢献ガイド、Rules評価レポート、npm梱包内容の検査を追加した。現在のバージョンは0.1.0-dev.0で、公開候補を確認する段階にある。リリース承認、npm公開、Webサイトの公開は行っていない。

## ローカルの確認を再現する

```sh
npm ci
npx playwright install chromium firefox webkit
npm run check
```

`check` は実APIを呼ばない。従来の型検査・lint・Vitest・ビルド・配布検査・E2Eに、次の2コマンドを加えた。

| コマンド | 確認する内容 |
| --- | --- |
| `npm run check:package` | 3パッケージのnpm梱包予定ファイル、README・ESM・型・LICENSE、バージョン整合、private設定 |
| `npm run eval:rules` | 既存12シナリオのRules回帰結果。JSONはtest-results/rules-evaluation.jsonへ出力 |

梱包検査は `npm pack --dry-run --json --ignore-scripts --offline` を使用する。npmへ送信せず、tarballの作成も行わない。成果物の利用可否は既存の `check:distribution` が別途、ソースのないconsumer環境で確認する。

## 12シナリオは人の意味評価を待っている

入力と期待値は `packages/core/test/fixtures.ts`、評価コマンドは `scripts/evaluate-rules.ts` にある。固定時計・同じ辞書・同じRulesを使い、期待値と結果が違えば終了コード1を返す。評価日時はシナリオ用の固定時刻で、実行時刻ではない。

| 分割 | シナリオ | 現在の回帰基準 |
| --- | --- | --- |
| development | 初訪問 | 根拠不足で見送り |
| development | 機能中心 | 機能ガイド |
| development | 料金中心 | 料金ガイド |
| development | 事例中心 | 利用例ガイド |
| development | 複数の関心 | 候補差が小さく見送り |
| development | 興味の変化 | 新しい観測が強い料金ガイド |
| development | 別製品混在 | 別製品の観測を除き料金ガイド |
| development | 単発の長時間放置 | 根拠不足で見送り |
| holdout | 推薦由来のみ | 自然な関心の根拠にはせず見送り |
| holdout | 期限切れ候補 | 期限切れを除外し、残りは閾値未満 |
| holdout | 表示条件を満たした既読候補 | 該当候補を除外し、残りは閾値未満 |
| holdout | すべて弱い入力 | 閾値未満で見送り |

12件の成功を「推薦精度100%」とは呼ばない。期待値は実装時に作成した回帰基準で、オーナーによる意味のレビューは未実施。holdoutも回帰試験で参照済みなので、独立した未知データへの評価としては扱わない。

意味評価は、各場面で許容するcontentId集合または見送りを人が確認してから行う。Rules・ラベル中心Jev・辞書付きJevには、同じ観測と候補集合を渡す。候補除外、時計、共通ポリシーを固定し、結果だけでなく見送り率、入力トークン、所要時間を残す。スコアとprovider confidenceは別々に記録する。少数の結果で統計的優位やCV改善を主張しない。

Jevの比較実行はまだ用意していない。既存の `test:jev` は合成データ1回を既定とする疎通試験であり、上記の品質比較とは異なる。キーの設定と明示的な実行許可を受けてから使う。

## 公開前に残る確認

| 項目 | 状態・次の確認 |
| --- | --- |
| パッケージ名と公開権限 | `@imicue/*` はローカル名。npm上の利用可否と権限は未確認 |
| パッケージ設定 | private=true、開発バージョンを維持。公開時のバージョン・exports・依存公開順を別途確認 |
| 実API | 疎通・判断品質・料金・遅延が未検証 |
| Safari製品版・モバイル実機 | WebKitでのE2Eとは別に確認が必要 |
| 意味評価 | 人による許容結果のレビューと、方式間の実測比較が未実施 |
| 公開用サイト | デモはローカル検証用。配信サービス、HTTPS、公開用の説明・接続先の確認が必要 |
| 本番判定サーバー | 共有の利用制限基盤と運用設計が必要。開発用メモリ制限だけでは公開しない |
| 公開の承認 | 成果物・費用・制約を確認した後、オーナーが公開範囲を判断 |

公開先に関する個人の運用情報やアカウント情報は、このリポジトリに保存しない。公開用の手順は汎用的に記載し、環境固有の設定は公開操作を行う際に扱う。

公開準備の資料とローカル確認は揃ったが、上表の未実施事項を含むリリース承認はまだ受けていない。次はSafari製品版の確認と、許可後のJev疎通・人によるシナリオレビューを進める。
