読書メモの検索方法を見た人には、検索ガイドを。
読みかけの本を整理している人には、記録の使い方を。

Imicueは、閲覧や操作の記録をもとに、登録した候補から案内先を選ぶOSSライブラリです。
案内カードやリンクの見せ方は、サイトに合わせて実装できます。

案内の変化を試す →導入手順を見る

見る内容が変わると、案内も変わる。

架空の読書記録アプリを使った比較デモです。用意した記録をブラウザ内のルールで判定します。

案内先は事前に登録します。実際のサイトでは、条件を満たした表示や操作を記録し、案内するIDまたは見送りを返します。表示されたことだけで、読了や購入意思を断定しません。

記録する対象と、案内先はサイト側で決める。

ページ、資料、事例、相談窓口。登録した最大100件の候補から、次の案内を選べます。

HTMLにIDを付け、辞書で内容を説明する

計測したい要素に登録済みIDを付けます。辞書には要素の説明、関連する話題、案内候補を定義します。

<section data-imicue-signal="search-overview">
  読書メモの検索方法
</section>

判定結果を、サイトのUIに使う

返されるのは候補のIDまたは見送りです。カードやインラインリンクなど、表示する場所と形を選べます。

{ type: 'recommend', contentId: 'search-guide', … }
// または
{ type: 'abstain', reason: 'ambiguous', … }
APIキーなしで始める
ルール判定（Rules）は、辞書に登録した関連と回数・時間を使い、ブラウザ内で動作します。
説明の意味からも比較する
AIモデルのJevを使う場合は、説明文を含む情報をサーバー経由で評価します。APIキーと利用料が必要です。
ページ移動後の記録も使う
標準はメモリ内で保持。同意後にsession保存を有効にすると、同じタブでページを移動しても記録を引き継げます。

ローカルで、
実際の計測を試す。

ソースコードを取得すると、閲覧や操作を記録するデモが動きます。Rulesの利用にAPIキーは不要です。

Node.js 24.14.0 / npm 11.9.0
開発版をソースから利用できます。npmパッケージは未公開です。

ターミナル
git clone https://github.com/blanket11/imicue.git
cd imicue
npm ci
npm run dev

起動後、http://127.0.0.1:5183/を開き、計測を許可して「計測を開始」を押してください。

導入前に確認すること

記録は同意後に開始
初期状態では計測・保存・判定通信を始めません。DOM本文やフォームの入力文を収集する機能はありません。
根拠が足りなければ見送る
候補を絞れない場合も案内を出しません。見送りや障害時も、サイト本来の機能を使えるように組み込みます。
開発版として検証して使う
APIや初期値は変更される場合があります。利用サイトでの推薦品質や効果は未検証です。検証範囲と制約を確認してください。
