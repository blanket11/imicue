案内先の表示例

    PACELETの案内先を要約した表示例です。フォームの操作とページ移動はローカルデモで試せます。

    HOW IT WORKS

    記録する対象と、案内先はサイト側で決める。

    HTMLと辞書を設定し、判定結果をいつものUIに使えます。

    01

    HTMLにIDを付ける

    計測したい要素に、辞書へ登録したIDを付けます。

    <section
  data-imicue-signal="feature-board">
  担当と状態を一覧するボード機能
</section>
    02

    辞書で説明する

    何を見たか、どの案内と関係するかを定義します。

    // 案内候補の設定の一部
relatedSignalIds: [
  'feature-board'
]
    03

    判定結果をUIに使う

    候補のIDか見送りを受け取り、カードやリンクを表示します。

    {
  type: 'recommend',
  contentId: 'product-features', …
}

    Rulesで始める辞書の関連と回数・時間を使ってブラウザ内で判定。APIキーは不要です。

    Jevで意味を比較する説明文をサーバー経由で評価する方法も選べます。APIキーと利用料が必要です。

    ページをまたいで使うsession保存を選ぶと、同じタブの直近30分の記録を引き継げます。

    詳しい導入手順 ↗

    COLLECTION & CONTROL

    サイトの方針に合わせて使う。

    計測開始を選べる

    ページ表示時の自動開始と、既存の同意管理に連携した手動開始に対応。計測の無効化も選べます。

    必要な情報だけ記録

    登録したIDと数値を扱います。DOM本文やフォームの入力文を自動収集する機能はありません。

    根拠が足りなければ見送る

    候補を絞れないときは案内を表示しません。見送り時も、サイト本来の機能を使えるように組み込みます。
