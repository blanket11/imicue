# Imicue

**サイト内の閲覧や操作に合わせ、次に案内する情報を選ぶOSSライブラリです。**

例えば、読書メモの検索方法を見ている人には検索ガイドを、読みかけの本の整理方法を見ている人には関連する案内を候補にできます。登録した行動と案内先を「辞書」で結び、候補IDか、案内を見送る結果を返します。案内カードやリンクの表示は、利用サイト側で組み込みます。

[紹介サイト・操作例](https://imicue.push.tokyo/) · [使い方と仕様](docs/README.md) · [貢献方法](CONTRIBUTING.md) · [Apache-2.0 License](LICENSE)

現在は **0.1.0-dev.0の開発版**です。ソースとローカルデモを公開しています。npmパッケージと配布用CDNは未公開で、APIやデータ形式は変更される場合があります。このREADMEは、このブランチにあるコードの手順です。

## できること

- 登録したセクションの表示と、明示的に登録した操作を集計する。
- 辞書の対応関係を使う **Rules** で、外部APIなしに候補を選ぶ。意味の説明を使う **Jev** へ、サーバーから接続する構成も選べる。
- 最大100件の案内先を評価し、根拠が少ない場合や候補が拮抗する場合は案内を見送る。
- 同じタブのページ移動後も記録を使い、閲覧条件を満たした案内先や完了した案内先を一定期間、再案内から外す。

表示時間は読了時間を示すものではありません。Rulesのスコアも、関心や購入の確率として扱いません。入力フォームの文章やDOM本文を自動収集せず、登録済みのIDと数値を扱います。

## ローカルデモを動かす

Node.js **24.14.0** と npm **11.9.0** を使います。nvmを使う場合は、リポジトリ内で `nvm install && nvm use` を実行してください。

```sh
git clone https://github.com/blanket11/imicue.git
cd imicue
npm ci
npm run dev
```

[ローカルデモ](http://127.0.0.1:5183/)を開き、次の順に確認します。APIキーは不要です。

1. 計測の許可にチェックを入れ、「計測を開始」を押します。
2. 「読書メモの検索例を開く」を押します。
3. 判定後に、確認パネルの候補と辞書の説明を確認します。判定の開始間隔は最低15秒です。

候補の表示と集計を確認できれば、計測からRules判定まで動いています。初期設定では記録をメモリに保存し、ページを読み直すと消えます。同意を撤回すると、記録と案内の抑制履歴を削除します。

紹介サイトのデモは、あらかじめ用意した閲覧記録を切り替える説明用です。ブラウザ上の表示時間やページ移動を確かめるには、このローカルデモを使ってください。

## 普通の製品サイトで自動の案内を試す

```sh
npm run dev:next
```

[PACELETの製品サイトデモ](http://127.0.0.1:5186/)は、架空のチーム向け進行管理サービスです。計測は自動で始まります。ボード機能と予定表の説明を順に閲覧すると、記録に応じて右下に次の案内が出ます。判定や表示のボタンを操作する必要はありません。

機能・事例・資料請求・お問い合わせの4種類を試せます。フォームはデモ内で完了し、入力内容を送信・保存しません。記録は同じタブのページ移動・再読み込み後も30分保持します。確認する順序と案内が出ないときの調べ方は、[製品サイトデモの手順](docs/guides/product-demo.md)を参照してください。

## 計測の開始方法を選ぶ

[開始モードのデモ](http://127.0.0.1:5183/collection/)では、ページ表示時の自動開始、ボタンからの手動開始、計測の無効化を試せます。「読書メモの検索例を開く」を押し、集計と案内の変化を確認してください。

停止は記録を保持し、リセットは保存分も削除します。ページ移動時の復元も確認できます。[操作手順](docs/guides/collection.md#ローカルで確かめる)を参照してください。

### ページ移動後の記録を試す

[ページ横断デモ](http://127.0.0.1:5183/?storage=session)では、同じサイト・同じタブの直近30分の記録を使います。各ページで許可して開始すると、前のページの記録が戻ります。操作順と削除の確認は、[ページ横断の手順](docs/guides/local-demos.md#ページ移動後の記録を試す)を参照してください。

SDKでは `storage: 'session'` を指定し、計測開始時に記録を復元します。自動開始か手動開始かはサイト側で選べます。同意状態そのものは保存しません。別ドメインや別端末をまたぐユーザー識別は行いません。

## SDKの構成

| パッケージ | 役割 |
| --- | --- |
| `@imicue/core` | 辞書の検証、集計、Rules、候補の除外と見送り |
| `@imicue/browser` | 計測の開始・停止、DOM属性の計測、保存、判定の実行と購読 |
| `@imicue/server` | 固定辞書の解決、HTTP入力と利用量の検査、Jev接続 |

次は初期化の形です。辞書、開始・停止、結果の表示を含む例は [SDKを組み込む](docs/guides/integration.md)にあります。パッケージはリポジトリ内でビルドして使用します。

```js
import { createTracker } from '@imicue/browser';
import { createRulesEngine } from '@imicue/core';
import { definition } from './definition.js';

const tracker = createTracker({
  definition,
  pageId: 'home',
  collection: { mode: 'auto' }, // 初期化時に計測開始
  engine: createRulesEngine(),
  storage: 'memory',
});

// 停止と保存済み記録の削除は、サイト側の操作から制御できます。
// tracker.stop();
// tracker.reset();
```

`auto` は初期化時に計測を開始します。`manual` は `start()` まで待機し、`disabled` は計測を無効にします。Imicueは同意UIや同意要否の判断を持たず、利用サイトが開始タイミングを決めます。Jevを使う場合もAPIキーはサーバー側で扱います。

`collection` を省略した既存コードは、従来どおり `setConsent('granted')` → `start()` が必要です。詳しくは[開始モードと移行方法](docs/guides/collection.md)を参照してください。

## 検証と利用上の制約

通常のテストは実APIを呼びません。開発環境と実行する検査は [貢献ガイド](CONTRIBUTING.md)、判定品質と検証範囲は [100候補の評価記録](docs/21-candidate-scale.md)を参照してください。合成データでの期待値との一致は、実サイトでの推薦精度や効果を示すものではありません。

macOSでPlaywrightのChromium・Firefox・WebKitを検証しています。Safari 26.4製品版では[基本デモ・ページ横断・Jev接続を確認](docs/16-safari-verification.md)していますが、100候補の追加試験は未完です。iPhone/iPadの実機検証も残っています。

通常の同一documentのDOMが対象です。iframe、Shadow DOM、要素の重なりの完全な判定には対応しません。60秒無操作で表示時間の計測を止めるため、操作せず長文を読む時間も停止対象です。Jevを本番で使うには、共有カウンターを持つ利用制限を別途実装する必要があります。詳しくは [セキュリティとプライバシー](docs/05-security-and-privacy.md)を参照してください。

不具合や使い方の相談は [GitHub Issues](https://github.com/blanket11/imicue/issues)へお願いします。APIキーや個人の情報を含むログは投稿しないでください。
